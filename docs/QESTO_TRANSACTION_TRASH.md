# Корзина операций Qesto — решение D02

Дата: 2026-09-06.

## Решение пользователя

Ручное удаление операции переносит её в корзину. Повторная синхронизация/импорт не должны самостоятельно возвращать эту же операцию. Пользователь может явно восстановить её. После появления собственного сервера удаление и восстановление должны распространяться на остальные устройства Qesto.

Это изменения финансовой истории **Qesto**, не удаление операций в самом банке.

## Реализация

- Используется существующий `CanonicalTransactionStatus.deleted`, без физического удаления canonical record, receipt и source evidence. JSON-контракт Synoball и codec schema version 6 не менялись.
- Новый экран общий для Android и desktop: поиск, восстановление одной операции и «Восстановить всё» с подтверждением. Автоматического срока очистки и кнопки окончательного удаления из корзины нет.
- Desktop: «Транзакции → Корзина» и «Настройки → Корзина». Android: корзина в заголовке истории действий и экрана найденных уведомлений.
- Удалённые операции исключены из обычного списка и финансовых расчётов. Банковский наблюдаемый баланс не изменяется: удаление записи в Qesto не переводит деньги в банке.
- Перед удалением исходный `posted/pending/reversed` сохраняется в техническом теге. Явное восстановление возвращает исходный статус, тот же canonical ID, точную сумму, пользовательскую категорию/название и ссылку на чек. Старые deleted records без такого тега используют имеющиеся статусные теги, иначе прежнее поведение posted.
- Повторный delete/restore идемпотентен. Старый открытый редактор и отмена прежнего редактирования не могут неявно воскресить удалённую запись.
- Совпадение canonical/provider identity учитывает сохранённые ограничения entity/account/currency/connection scope. Известная удалённая запись даёт `suppressedTransactionIds`, а не created/active merge; новая source evidence сохраняется без изменения удалённых финансовых значений и даты удаления. Повторы одинакового наблюдения не размножают evidence.
- Похожая запись без надёжного совпадения identity остаётся pending review: сходство не является основанием ни для автоматического восстановления, ни для безусловного отбрасывания другой покупки.
- Отчёт Сбера показывает отдельные счётчик и строковый статус «В корзине». Suppression отражается также в warnings import batch; уведомление можно подтвердить после успешного сохранения этого решения.
- Если импортированный счёт был удалён отдельной отменой импорта, восстановление операции создаёт virtual account с исходным ID и нулевым **неподтверждённым** балансом. Старый банковский баланс не выдаётся за актуальный.
- После ошибки сохранения восстановления экран показывает ошибку и кнопку повторной попытки. Повтор сохраняет ту же операцию, не создавая новый canonical record или ещё одно restore event.

## Фундамент будущей серверной синхронизации

В существующий сохраняемый журнал событий добавляются `transaction.deleted` и `transaction.restored` с subject canonical ID, entity, actor, changedAt и итоговым статусом. Deletion event содержит снимок метаданных счёта для локального восстановления при отсутствующем счёте. Audit trail сохраняет намерение пользователя.

**Серверная доставка, outbox acknowledgements, авторизация устройств и разрешение конфликтов между устройствами ещё не реализованы.** Эти события — локальный фундамент, а не обещание уже работающего удаления на других устройствах. При подключении сервера операции delete/restore должны переноситься как явные команды с устойчивыми ID; обычный source refresh не имеет права отменять пользовательское удаление.

## Границы

- Полный сброс «Удалить все данные Qesto» — отдельная существующая безвозвратная операция; текст подтверждения теперь явно включает корзину. Состав удаления CEF profiles/PIN/cookies (D05) этим решением не менялся.
- Нестабильные старые идентификаторы Excel/Sber и сложное сопоставление перекрывающихся OCR кадров остаются пунктами S02 аудита. Корзина не превращает ненадёжный provider ID в доказанную identity; массового исправления/сопоставления истории не выполнялось.
- Пользовательские финансовые файлы и банковская сессия не использовались для тестов. Установленный EXE не обновлялся в рамках этой доработки.
