# Реализация безопасности Qesto: пофайловый разбор

Этот документ объясняет программную реализацию защиты Qesto. Краткие правила
эксплуатации и выпуска находятся в [`SECURITY.md`](../SECURITY.md), а устройство
финансового ядра — в
[`SYNOBALL_CORE_WALKTHROUGH_RU.md`](SYNOBALL_CORE_WALKTHROUGH_RU.md).

Qesto не является сертифицированным банковским хранилищем. Цель реализованных
мер — не сделать приложение неуязвимым, а закрыть конкретные риски текущей
архитектуры: открытый JSON с финансовой историей, незашифрованный Android-буфер
уведомлений, случайную публикацию APK с debug-ключом, неограниченный разбор
недоверенных файлов, открытый LAN API и запуск неподтверждённых бинарников.

## 1. Общая схема

```text
UserFinancialData / SynoballState
              │ JSON
              ▼
EncryptedLocalKeyValueStore
              │ AES-256-GCM + новый nonce + AAD(storage key)
              ├──────── ciphertext envelope ───────► platform store / store.json
              │
              └──────── 32-byte master key ───────► OS protected storage

Android notification
              │ JSON array
              ▼
NotificationInbox
              │ AES/GCM/NoPadding
              ├──────── ciphertext ────────────────► private SharedPreferences
              └──────── non-exportable key ───────► Android Keystore
```

Ключ и зашифрованные данные намеренно хранятся раздельно. Копии одного
`store.json` недостаточно для чтения финансовой истории. Для Android-уведомлений
используется отдельный ключ: компрометация одного формата не раскрывает второй.

## 2. Шифрование финансовых данных

### `apps/qesto_app/lib/data/persistence/encrypted_local_key_value_store.dart`

Файл добавляет декоратор над существующим `LocalKeyValueStore`.

#### `SecureStringStore`

Минимальный интерфейс из `read` и `write` отделяет криптографию от конкретного
плагина. В production его реализует `PlatformSecureStringStore`, а тесты
подставляют хранилище в памяти. Благодаря этому тесты проверяют настоящий
AES-GCM, не обращаясь к системному vault.

#### `PlatformSecureStringStore`

Передаёт операции в `FlutterSecureStorage`. В защищённом хранилище ОС находится
только случайный 32-байтовый мастер-ключ
`qesto.local-storage.master-key.v1`. Финансовый JSON туда не помещается: он
может быть большим, а системные vault рассчитаны на небольшие секреты.

#### `EncryptedLocalKeyValueStore.writeString`

1. Получает или создаёт мастер-ключ через `_masterKey()`.
2. Кодирует строку как UTF-8.
3. Создаёт новый случайный nonce для каждой записи.
4. Шифрует значение алгоритмом AES-256-GCM.
5. Передаёт логический ключ хранилища как AAD — дополнительные
   аутентифицируемые данные.
6. Сохраняет версионированный envelope:

```json
qesto:aes-gcm:v1:{
  "v": 1,
  "nonce": "base64...",
  "ciphertext": "base64...",
  "mac": "base64..."
}
```

AAD не шифруется, но входит в проверку подлинности. Поэтому копирование
валидного шифротекста из ключа `first` под ключ `second` не пройдёт проверку.
MAC также заставляет чтение завершиться ошибкой после изменения ciphertext,
nonce или тега.

#### `EncryptedLocalKeyValueStore.readString`

- Значение с префиксом `qesto:aes-gcm:v1:` декодируется, проверяется и
  расшифровывается.
- Ошибка формата, неверный ключ или подмена данных превращаются в
  `EncryptedStorageException`. Повреждённые данные не выдаются приложению как
  корректная финансовая история.
- Значение без префикса считается legacy plaintext. После успешного чтения оно
  сразу записывается заново уже в зашифрованном виде. Это автоматическая
  однократная миграция существующих установок без отдельной схемы БД.

`_masterKeyFuture` кеширует загруженный ключ на время процесса. Системное
защищённое хранилище не открывается заново для каждого чтения и сохранения.
Сам ключ в обычный JSON и Git не попадает.

### `apps/qesto_app/lib/data/repositories/local_qesto_repository.dart`

`LocalQestoRepository` теперь по умолчанию создаёт
`EncryptedLocalKeyValueStore` для `qesto.user-financial-data.v1`. Через него
проходят счета, операции, категории, бюджет и состояние Synoball.

Публичный кеш акций хранится отдельно в `publicStore`. Его шифрование не даёт
конфиденциальности, потому что те же акции приходят из публичного HTTP API, но
создавало лишние обращения к secure storage и AES. Разделение сохраняет защиту
пользовательских финансовых данных без ненужных расходов для публичного кеша.

Конструктор принимает обе зависимости явно. Это позволяет тестам и будущим
реализациям хранилища подменять их без изменения repository.

### `apps/qesto_app/lib/data/persistence/local_key_value_store_io.dart`

Desktop-хранилище по-прежнему записывает JSON через временный файл и backup:

1. новый снимок полностью записывается в `.temporary` с `flush`;
2. старый основной файл переименовывается в `.backup`;
3. временный файл атомарно становится основным;
4. после успеха backup удаляется;
5. при ошибке переименования основной файл восстанавливается.

Чтение теперь сначала проверяет основной файл, затем backup. Если основной JSON
повреждён, но backup валиден, данные восстанавливаются из него. Если оба
существующих снимка повреждены, ошибка не маскируется под «пустой аккаунт».

Полный `store.json` намеренно не кешируется в памяти. Такой кеш был бы немного
быстрее, но два одновременно работающих процесса Qesto могли бы сохранить
устаревшие снимки и затереть изменения друг друга.

### `apps/qesto_app/lib/app/qesto_app.dart`

Команда удаления пользовательских данных теперь очищает не только финансовое
хранилище repository, но и временный `NotificationInbox` через platform
channel. `MissingPluginException` допустим на платформах без Android listener.

## 3. Защищённый буфер Android-уведомлений

### `apps/qesto_app/android/app/src/main/kotlin/ru/qesto/qesto/NotificationInbox.kt`

Банковские push могут содержать сумму, магазин, остаток и последние цифры
карты. Раньше JSON-массив находился в `SharedPreferences` открытым текстом.
Теперь он шифруется `AES/GCM/NoPadding`.

`encryptionKey()` ищет ключ `qesto.notification-inbox.v1` в
`AndroidKeyStore`. Если ключа ещё нет, `KeyGenerator` создаёт AES-ключ с
назначениями encrypt/decrypt, режимом GCM и без padding. Материал ключа не
экспортируется в файл приложения. Полученный `SecretKey` кешируется только на
время процесса, чтобы не открывать KeyStore при каждом push.

`persist()` сериализует список в JSON, генерирует GCM IV, шифрует массив и
сохраняет строку вида:

```text
qesto:aes-gcm:v1:<base64 iv>:<base64 ciphertext-with-tag>
```

`loadItems()` поддерживает безопасную миграцию старого открытого массива:
возвращает флаг `needsRewrite`, после чего следующее чтение или изменение
перезаписывает список зашифрованным. Если шифротекст повреждён или Android
инвалидировал ключ, inbox удаляется вместе со старой записью ключа. Буфер
временный, поэтому потеря нескольких необработанных уведомлений безопаснее,
чем использование частично разобранных данных.

Дополнительные ограничения:

- максимум 100 уведомлений;
- срок хранения — 7 суток;
- обновление с тем же Android `notificationKey` заменяет старую версию;
- просроченные элементы удаляются при чтении и сохранении;
- неизменившийся список не шифруется и не записывается заново;
- `@Synchronized` не позволяет параллельным notification callbacks потерять
  изменения внутри одного процесса.

### `apps/qesto_app/android/app/src/main/kotlin/ru/qesto/qesto/MainActivity.kt`

Platform channel получил команду `clearNotifications`, которой пользуется
экран удаления данных. Чтение и удаление отдельных записей продолжают идти
через единственный `NotificationInbox`, поэтому Flutter-код не видит ключ и не
работает с шифротекстом напрямую.

## 4. Android backup, HTTP и подпись APK

### `apps/qesto_app/android/app/src/main/AndroidManifest.xml`

- `android:allowBackup="false"` отключает обычный Android backup.
- `dataExtractionRules` и `fullBackupContent` дублируют запрет для разных
  версий Android.
- `android:usesCleartextTraffic="false"` запрещает незашифрованный HTTP в
  release/main-конфигурации.

Backup отключён потому, что ciphertext без ключей Android Keystore после
переноса на другое устройство не расшифруется. Это предотвращает нерабочее
«восстановление» и уменьшает риск копирования финансовых данных.

### `apps/qesto_app/android/app/src/main/res/xml/data_extraction_rules.xml`

Запрещает cloud backup и device-to-device transfer для файлов приложения.

### `apps/qesto_app/android/app/src/main/res/xml/backup_rules.xml`

Эквивалентное правило для Android-версий, использующих старый формат full
backup.

### `apps/qesto_app/android/app/src/debug/AndroidManifest.xml`

Debug overlay явно разрешает cleartext HTTP. Это нужно только для локального
сервиса акций через `localhost`, `127.0.0.1` или `adb reverse`; release остаётся
закрытым.

### `apps/qesto_app/android/app/build.gradle.kts`

Release больше не подписывается общедоступным debug-сертификатом автоматически.
Gradle загружает `android/key.properties`, проверяет наличие `storeFile`,
`storePassword`, `keyAlias` и `keyPassword`, затем создаёт release signing
config. Release-задача завершается ошибкой, если приватный ключ не настроен.

Переменная `QESTO_ALLOW_DEBUG_RELEASE_SIGNING=1` оставлена только для одноразовой
локальной проверки release-режима. Такой APK нельзя публиковать.

### `apps/qesto_app/android/key.properties.example`

Шаблон показывает обязательные поля без реальных секретов. Настоящий
`key.properties`, `*.jks` и `*.keystore` исключены через Android `.gitignore`.
Приватный keystore должен храниться вне репозитория и иметь отдельную
зашифрованную резервную копию.

## 5. Ограничение недоверенных файлов

Файл, выбранный пользователем, считается недоверенным. Проверка только значения
`Content-Length` недостаточна: Android content provider может не сообщить
размер или сообщить его неверно. Поэтому лимит повторно применяется во время
реального чтения потока.

### `apps/qesto_app/android/app/src/main/kotlin/ru/qesto/qesto/MainActivity.kt`

`copyLimited()` читает поток блоками по 16 КБ, считает фактическое число байтов
и прекращает работу после превышения лимита. Один helper используется для
выписок и изображений чеков.

Установлены пределы:

| Данные | Лимит |
|---|---:|
| PDF/XLSX/TXT выписка | 20 МБ |
| Изображение чека | 20 МБ |
| PDF | 500 страниц |
| Извлечённый текст | 5 242 880 символов |

PDF целиком читается в ограниченный массив, а `PDDocument` закрывается через
`use`. Тяжёлый разбор выполняется в фоновом потоке; в UI thread возвращается
только результат или контролируемая ошибка.

### `apps/qesto_app/lib/features/statement_import/data/bank_statement_file_service_native.dart`

Те же ограничения повторены на Dart-стороне для Android platform-channel и
Windows file picker. Повторная проверка нужна, чтобы защита не зависела от одной
платформенной реализации. На Windows PDF обрабатывается через `Isolate.run`,
поэтому большой допустимый документ не блокирует интерфейс.

### `apps/qesto_app/web/pdf_statement_reader.js`

Web reader ограничивает исходный PDF 20 МБ, документ 500 страницами и итоговый
текст 5 МиБ символов. Счётчик проверяется после каждой страницы, поэтому
огромная строка не накапливается бесконтрольно до конца документа.

### `apps/qesto_app/lib/features/statement_import/services/universal_excel_statement_adapter.dart`

XLSX/XLSM является ZIP-архивом, поэтому маленький входной файл может
распаковаться в гигабайты. `_validateExcelArchive()` до декодирования читает
центральный каталог ZIP и проверяет:

- размер входного файла не больше 20 МБ;
- не больше 5000 ZIP entries;
- суммарный заявленный распакованный размер не больше 100 МБ;
- структура центрального каталога не выходит за границы массива;
- ZIP64 отклоняется как неподдерживаемый формат.

После открытия workbook дополнительно разрешено не больше 50 листов, 10 000
строк и 80 столбцов на лист. XLSM читается как таблица; макросы приложением не
запускаются.

Эти проверки уменьшают риск исчерпания памяти и CPU, но не являются полноценным
антивирусом. Парсер и его зависимости всё равно следует регулярно обновлять.

## 6. Речь и цепочка поставки Whisper

### `apps/qesto_app/android/app/src/main/kotlin/ru/qesto/qesto/MainActivity.kt`

На Android голосовой ввод запускается только через
`SpeechRecognizer.createOnDeviceSpeechRecognizer`. Если Android ниже API 31
или локальная модель недоступна, приложение возвращает
`voice_on_device_unavailable` и просит установить русский языковой пакет. Оно
не переключается незаметно на облачное распознавание. В intent также передаётся
`EXTRA_PREFER_OFFLINE=true`.

Это ограничивает отправку финансовой фразы внешнему speech provider, но
фактическая реализация системного распознавателя контролируется прошивкой
устройства. Пользователь должен доверять ОС и установленному языковому пакету.

### `apps/qesto_app/windows/whisper/setup_runtime.ps1`

Windows использует локальный `whisper.cpp`. Скрипт теперь:

- закрепляет версию бинарного архива;
- проверяет SHA-256 архива до распаковки;
- удаляет повреждённый кеш и скачивает архив повторно;
- закрепляет конкретную revision модели вместо плавающей ветки `main`;
- проверяет SHA-256 модели.

Это защищает от случайной подмены, повреждённой загрузки и незаметного изменения
файла по прежнему URL. При сознательном обновлении Whisper разработчик должен
отдельно проверить источник и заменить закреплённые хеши.

## 7. Web и внешние ссылки

### `apps/qesto_app/web/index.html`

Meta CSP ограничивает источники скриптов, workers, изображений, шрифтов и
сетевых запросов; запрещает плагины через `object-src 'none'`, подмену base URL
и отправку форм на чужие домены. `referrer=no-referrer` не передаёт адресу
внешнего сайта URL страницы Qesto.

Meta CSP — защита внутри документа, но production hosting должен также отдавать
CSP и остальные заголовки через HTTP. Рекомендуемый набор перечислен в
`SECURITY.md`.

### `apps/qesto_app/lib/core/platform/external_url_launcher_web.dart`

Web launcher принимает только схемы `http` и `https`. Ссылка открывается с
`rel="noopener noreferrer"`, поэтому новая вкладка не получает доступ к
`window.opener` и не получает referrer.

### `apps/qesto_app/lib/features/benefits/deal_details_screen.dart`

Перед переходом проверяются URI и host. Пользователь видит домен и явно
подтверждает выход из Qesto. Это снижает риск незаметного перехода по вредной
ссылке из импортированной акции; содержимое внешнего сайта приложение всё равно
не контролирует.

## 8. Локальный сервис акций

### `scripts/run_deals_service.cmd`

Сервис по умолчанию слушает только `127.0.0.1`, а не все сетевые интерфейсы.

### `scripts/run_qesto.py`

- для Android по USB сначала настраивается `adb reverse`;
- без forwarding приложение не открывает порт в LAN автоматически;
- LAN-доступ требует явного `--allow-lan` и сопровождается предупреждением;
- удалённое не-Android устройство также требует `--allow-lan`.

### `services/deals_ingestion/qesto_deals/__main__.py`

При запуске читает два необязательных параметра окружения:

- `QESTO_DEALS_SYNC_TOKEN` — токен ручного запуска синхронизации;
- `QESTO_DEALS_ALLOWED_ORIGINS` — дополнительный список разрешённых browser
  origins.

Токен не хранится в исходниках и не встраивается в Flutter Web.

### `services/deals_ingestion/qesto_deals/api.py`

`POST /sync` выключен, пока токен не задан. При включении ожидается
`Authorization: Bearer ...`; строки сравниваются через `hmac.compare_digest`.

CORS больше не возвращает `Access-Control-Allow-Origin: *`. Разрешены
localhost origins и явно настроенный allowlist. Ответы содержат
`Cache-Control: no-store`, `X-Content-Type-Options: nosniff` и
`Referrer-Policy: no-referrer`.

`GET /offers` остаётся публичным по замыслу: он отдаёт общедоступные акции, а не
финансовые данные. При `--allow-lan` любой узел локальной сети сможет читать
этот endpoint, поэтому LAN-режим нельзя использовать в недоверенной сети.

## 9. Зависимости и автоматическая проверка

### `apps/qesto_app/pubspec.yaml` и `pubspec.lock`

Добавлены `cryptography` для AES-GCM и `flutter_secure_storage` для системного
хранилища мастер-ключа. Сгенерированные registrant/cmake-файлы Linux, macOS и
Windows подключают platform implementations secure storage; вручную их менять
не следует.

Версия приложения повышена до `1.0.11+12`, чтобы Android считал сборку новым
обновлением.

### `.github/dependabot.yml`

Dependabot еженедельно проверяет Dart/Flutter, Gradle и GitHub Actions. Он не
устанавливает обновления непосредственно пользователю: каждый PR всё равно
нужно просмотреть и прогнать через тесты.

## 10. Тесты защиты

### `apps/qesto_app/test/encrypted_local_key_value_store_test.dart`

Проверяет четыре свойства:

1. plaintext отсутствует в delegate, а чтение возвращает исходную строку;
2. legacy plaintext мигрирует после первого чтения;
3. ciphertext нельзя скопировать под другой logical key из-за AAD;
4. изменённый ciphertext отклоняется.

### `apps/qesto_app/test/user_financial_data_codec_test.dart`

Проверяет, что публичные акции используют отдельный `publicStore` и не попадают
в защищённое финансовое хранилище.

### `apps/qesto_app/test/excel_statement_adapter_test.dart`

Содержит искусственный ZIP central directory с распакованным размером больше
100 МБ и подтверждает отклонение archive bomb до декодирования workbook.

### `apps/qesto_app/test/deal_details_screen_test.dart`

Подтверждает появление диалога с доменом и возможность отменить внешний переход.

### `services/deals_ingestion/tests/test_api.py`

Проверяет выключенный `/sync`, отказ без Bearer-токена, успешный запрос с
токеном и отсутствие CORS-разрешения для постороннего origin.

## 11. Что эта защита не решает

- Разблокированное приложение держит расшифрованные данные в памяти процесса.
- Root, вредоносное ПО с правами пользователя, отладчик или скомпрометированная
  ОС могут читать память и ввод.
- Web-версия зависит от HTTPS, корректных server headers и отсутствия XSS. Код,
  выполняющийся в origin Qesto, работает с теми же правами, что приложение.
- AES-GCM не скрывает факт существования файла и приблизительный размер данных.
- Мастер-ключ пока не ротируется и не защищён отдельным PIN/биометрией Qesto.
- Удаление финансового ciphertext не гарантирует физическое стирание всех
  блоков flash/SSD и системных резервных копий ОС.
- Лимиты файлов снижают риск denial of service, но не доказывают безопасность
  сторонних PDF/Excel/OCR библиотек.
- Публичный сервис акций не должен принимать банковские секреты или персональные
  финансовые данные.

## 12. Проверка перед коммитом и релизом

```powershell
cd apps/qesto_app
flutter analyze
flutter test
flutter build apk --debug
flutter build web --release

cd ../../services/deals_ingestion
python -m unittest discover -s tests -v
```

Дополнительно нужно проверить `git status`, отсутствие `.env`,
`key.properties`, keystore и реальных выписок, а release APK подписывать только
приватным production-ключом.
