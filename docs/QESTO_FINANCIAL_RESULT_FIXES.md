# Пакет 2 — финансовый результат: офлайн-этап

Дата: 2026-09-08. Сборка **1.0.40+41**. Продолжение аудита и
`QESTO_SBER_RECONCILIATION.md`. Рабочее дерево до начала уже содержало
изменения предыдущих пакетов; они сохранены. Synoball canonical JSON schema
не менялась. Новые контрольные поля находятся в адаптерах/отчётах.

## Исправленные ошибки

1. История и список продуктов по-разному хешировали один provider account ID.
   Теперь используется одинаковое пространство идентификаторов.
2. Операция с неизвестным счётом назначалась первому счёту профиля, в том числе
   другого банка. Теперь денежный факт сохраняется на явно неопределённом
   виртуальном счёте, без выдуманного остатка; не теряется из Cash Flow.
3. При неполном обновлении продуктов не использовалась точная ссылка на уже
   известный счёт. Теперь она учитывается; отсутствие нового reference не
   переносит уже связанную операцию на первый счёт.
4. Валюта операции не проверялась при назначении счёта. Несовпадение теперь
   оставляет счёт неопределённым в нужной валюте.
5. Одинаковые имена продуктов могли заменить разные счета и их остатки.
   Сопоставление только по имени удалено.
6. Одинаковые последние четыре цифры сами по себе могли объединить продукты.
   Для мостика между разными ID нужна наблюдаемая связь карты со счётом;
   неоднозначные связи в одном snapshot не выбираются по порядку.
7. При объединении карты и счёта терялся альтернативный ID карты. В пределах
   snapshot сохраняются route aliases, которыми пользуются строки истории.
8. От порядка карточек DOM зависело, какой баланс останется: доступный остаток
   карты мог заменить баланс счёта. При явной связи главным является счёт.
9. Последние цифры самого счёта попадали в список привязанных карт. Теперь
   они сохраняются отдельно; подпись счёта не теряет свой суффикс.
10. История могла начинать чтение с восстановленной старой позиции прокрутки.
    Теперь перед чтением выполняется возврат наверх и ожидание загрузки.
11. Строки, прочитанные во время ожидания «Показать ещё», использовались лишь
    как сигнал готовности. Теперь каждое чтение сразу сохраняется в накопитель.
12. Перерисовка одной строки (например, pending → posted) могла оставить две
    версии в накопителе из-за изменившегося fingerprint. Новое наблюдение
    заменяет старое по identity строки в пределах текущего обхода.
13. Исчерпание лимита прокруток при отсутствии кнопки считалось полным обходом.
    Теперь это partial, пока не достигнута граница периода или устойчивый конец.
14. Слова «входящий перевод» в описании комиссии могли превратить явно
    отрицательную сумму в доход. Явный знак списания имеет приоритет.
15. Отдельная комиссия за внутренний перевод могла исключаться из Cash Flow.
    Это внешний расход, а не перемещение собственных денег.
16. Отменённая неоплаченная покупка могла стать POSTED. Явная отмена теперь
    CANCELLED; положительный возврат остаётся отдельным REFUND.
17. PDF-импорт не сверял распознанные строки и суммы с банковскими контролями.
    Теперь проверяются исходное число строк, поступления/списания и уравнение
    opening + inflows − outflows = closing. Расхождение показывает предупреждение;
    отсутствующие контролы не заменяются выдуманным начальным остатком.
18. Конечный остаток PDF выбирался только по самой поздней дате покупки, а в
    форме импорта округлялся до рублей. Теперь при наличии печатных контролей
    используется конечный остаток документа и передаётся exactBalanceMinor.

В отчёте синхронизации отдельно показано число сохранённых операций с
неопределённым счётом. Они входят в денежный поток, но не доказывают сверку
конкретного счёта. Ручной и фоновый результаты в таком случае partial.
Диагностика явно подписана как денежный поток **всего профиля**, не только Сбера.

## Не закрыто и не объявляется исправленным

- Живой обход CEF за весь выбранный период и банковский login/session acceptance:
  пользователь пока не может войти. Сохранённый HTML не заменяет эту проверку.
- PDF и HTML охватывают разные счета/временные рамки; 125 и 114 нельзя напрямую
  вычитать. Для полной сверки нужны документы по одинаковому периоду и счетам.
- Исторические неверные привязки/слияния не переписаны автоматически. Уже
  утраченные source facts не восстанавливаются догадками; нужен отдельный cutover.
- Полное постоянное mapping PDF ↔ web, разные банковские подключения,
  банковские aliases после смены routes и нетиповые совпадения last-four требуют
  следующего этапа identity. Новые aliases этого пакета действуют в snapshot.
- Не сопоставлены автоматически обе стороны внутренних переводов, возврат
  отдельной строкой web против net-суммы в PDF, комиссия, включённая в общую
  сумму, и весь набор старых provider/fingerprint IDs.
- Не создаётся фиктивный opening balance из текущего остатка минус Cash Flow.
  Внутренние переводы исключаются из общего Cash Flow, но должны участвовать
  в сверке отдельного банковского счёта; PDF-контроли считают все движения.

Это завершённый офлайн-подэтап пакета 2, **не закрытие всего финансового аудита**.
