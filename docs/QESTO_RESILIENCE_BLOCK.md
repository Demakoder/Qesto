# Второй блок: устойчивость и проверка сборок

Дата: 2026-09-10. Локальная Windows-версия: **1.0.44+45**.

## Границы этапа

Пользователь подтвердил работу фоновой синхронизации и отложил её полировку.
В этом этапе runtime/навигация/авторизация Сбера не менялись. Работа велась на
синтетических временных хранилищах и локальных файлах-примерах, без записи
в банковский сайт или финансовый профиль пользователя.

Android-сборка для телефона и проверка на устройстве **отложены по просьбе
пользователя**: на телефоне сначала понадобится установить свежий APK.
Компиляция Kotlin и тесты Dart не заменяют проверку AndroidKeyStore,
NotificationListener, разрешений, камеры и микрофона на устройстве.

## Исправления

### Android: расположение финансового хранилища

- Вместо ненадёжного выбора через `HOME`/рабочую папку используется приватный
  `Context.filesDir/Qesto/store.json`, полученный через узкий native channel.
- Перенос старого снимка сохраняет оригинал и использует recoverable write.
- Новый существующий снимок, включая пустой после удаления данных, имеет
  приоритет: старый файл не восстанавливает удалённые операции.
- При повреждении обоих снимков перенос останавливается; отсутствующий native
  путь не подменяется новой пустой базой. Проверяются границы app sandbox и ссылки.

### Android: очередь уведомлений

- Ошибка расшифровки больше не удаляет шифротекст и ключ автоматически.
- Для чтения шифротекста отсутствующий ключ не создаётся заново.
- Сохранение и подтверждение удаления используют проверяемый `commit`, а не
  асинхронный `apply`. Ошибка записи переводит очередь в состояние ошибки до
  перезапуска/явного очищения, вместо ложного успешного подтверждения.
- Native channel возвращает ошибку без содержимого уведомлений; listener
  не падает из-за ошибки хранения. Это не гарантирует захват новых уведомлений
  при неисправном хранилище: они не должны считаться успешно сохранёнными.
- Прежние ограничения очереди (100 элементов / 7 дней) не изменены.
  Отдельного интерфейса восстановления повреждённой очереди пока нет.

### Excel: факты, сводки и остатки

- Добавлен разбор повторяющихся месячных календарей: категории в строках,
  дни 1–28/31 в столбцах. Учитывается месяц каждого блока, итоговые строки
  и невозможные даты вроде 31 февраля не создают операции.
- При наличии детализации листы «Дашборт», «Итоги…», `total`, «План-факт»
  больше не используются как дополнительные расходы/доходы.
- Явно подписанные блоки месячных оценок капитала исключаются из движений.
  Отдельные подписанные дивиденды/купоны в таком блоке сохраняются как потоки.
- Матрица не продолжает читать следующий заголовок периода со старыми
  столбцами. Крупные суммы не принимаются за Excel-даты заголовка.
- Итоги, общий активный/пассивный доход, общий расход и норма сбережений
  не создают дополнительные денежные операции.
- Изменён только адаптер; схема Synoball не менялась. Уже сохранённые операции
  пользователя автоматически не пересчитывались и не удалялись.

### Windows OCR

WinRT отклонял путь изображения с прямыми слешами. Перед открытием файла путь
теперь нормализуется через `GetFullPath`; проверены оба варианта разделителей.

## Проверки

- Общий Flutter suite: **506 passed / 8 opt-in skipped**.
- `flutter analyze --no-pub`: **No issues found**.
- Реальный Excel corpus: **23 файла**, отдельный opt-in тест прошёл.
- Независимое чтение исходных XLSX/XLSM через openpyxl в read-only режиме:
  **8 283 импортированные строки**, 0 несовпадений сумм с исходными ячейками,
  0 повторно использованных ячеек внутри одного файла. Исходные книги не
  перезаписывались, макросы не запускались, формулы не пересчитывались.
- «Копия 6»: независимо сверены все **214** заполненных дневных сумм и их даты,
  общий расход **20 238 398 копеек**; лист «План-факт» не импортируется.
- «Копия 3»: 11 оценок капитала исключены из расходов; 4 строки дивидендов
  сохранены как доход. В «Копии 12» исключены 71 строка повторной сводки `total`.
- В «Копии 17» год 2024 относился к исключённой сводке оценок, а не к оставшимся
  операциям. Старые пороги количества/лет скорректированы только для этих
  подтверждённых случаев, а не для маскировки пропущенных операций.
- **8 subprocess crash cases**: реальный выход процесса во время каждого
  этапа записи/очистки; восстановление, освобождение блокировки, новая запись;
  после завершённой очистки повреждение primary не возвращает старые данные.
- Проверки Android location: 9 случаев переноса/повреждения/пустого снимка/
  конкурирующих вызовов/отсутствующего native path/границ sandbox.
- Нативные Windows bridges: **3 passed** — PDF (контрольная выписка: 125
  операций), OCR синтетического чека, Whisper синтетической русской WAV-фразы.
- Kotlin `:app:compileDebugKotlin --offline`: успешная компиляция; остаются
  предупреждения существующего Gradle/AGP/SDK окружения.
- Существующие тесты расписания, восстановления профиля, отключения и отмены
  синхронизации входят в общий успешный suite. Новый живой вход в Сбер не выполнялся.

Инструменты воспроизведения: `tool/storage_crash_regression.dart`,
`tool/excel_corpus_inventory.dart`, `test/excel_statement_corpus_test.dart`,
`test/excel_calendar_safety_test.dart`, `test/android_store_location_test.dart`.
Локальные финансовые отчёты находятся в игнорируемой `.codex_tmp`, не в Git.

## Что эти проверки НЕ доказывают

Совпадение суммы с ячейкой не доказывает, что каждая непопавшая ячейка во всех
23 сложных книгах правильно исключена. Полная независимая семантическая сверка
всех листов, формул-ссылок, планов, долгов и оценок капитала остаётся отдельной
задачей; полностью подтверждённый календарный пример здесь — «Копия 6».
Не обещаем универсальную поддержку произвольных Excel-файлов или автоматический
импорт снимков капитала как остатков счетов. Для ранее импортированных ошибок
нужна отдельная безопасная коррекция с предварительным сравнением, не повторный
слепой импорт и не удаление пользовательской истории.
