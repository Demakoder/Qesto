# Qesto — устойчивые идентификаторы источников, S02

Дата: 2026-09-06. Продолжение `QESTO_INGESTION_FIXES.md` и `QESTO_TRANSACTION_TRASH.md`.

## Граница пакета

Исправлены адаптеры уведомлений/SMS, Excel и банковских OCR-скриншотов, а также их экраны подтверждения. Каноническая финансовая схема Synoball и версия сохраняемого профиля не менялись. Новые SHA-256 идентификаторы относятся к источникам и наблюдениям, а не объявляются банковскими ID операций.

Нет массового переписывания истории: при новом импорте доказанная связь со старым наблюдением сохраняет прежний canonical ID. Связь сохраняется штатным evidence. Сопоставление включает записи в корзине; повтор источника не является восстановлением. Неоднозначные старые записи не распределяются по принципу «первое совпадение».

Изменения выполнены поверх прежнего dirty worktree. Пользовательские финансовые файлы, CEF-профили, PIN и банковская сессия не изменялись. Установленный EXE и ярлык не обновлены; commit/push не выполнялись.

## Уведомления и SMS

- ОС может использовать один notification key для разных покупок. Теперь он отделён от ID наблюдаемой операции.
- `notification-v2` включает entity, счёт, тип источника, package, native key, момент операции, точную сумму/валюту, направление и нормализованного продавца. Поля интерфейса уведомления, новый остаток, категория и deliveryVersion не входят в этот ключ.
- Повтор доставки и изменение текста/остатка при тех же финансовых фактах сохраняют идентичность. Идентичные покупки с разными native keys не схлопываются.
- Другая сумма/время под прежним native key отправляются на проверку, не перезаписывают предыдущую покупку. В ручном экране есть объяснение и подтверждение. Неоднозначный результат сопоставления с другими источниками/корзиной по-прежнему не форсируется.
- Обычные распознанные уведомления продолжают импортироваться автоматически. Неуспешные и требующие проверки доставки не удаляются из native inbox. Подтверждение и повтор после ошибки сохранения проверены; acknowledgment остаётся key + deliveryVersion.
- Ручное добавление/подтверждение поддерживает копейки. Старый общий редактор уведомлений пока доступен только для целых сумм; это отдельный UI precision долг, он не блокирует точный импорт.
- Legacy alias требует совпадения сохранённых source facts и package/key. Редактированные пользователем canonical fields не используются как доказательство прежних фактов.

Ограничение: два события с одинаковыми key, timestamp, суммой, направлением и продавцом невозможно доказанно различить по имеющемуся payload. Это не обещание универсальной банковской идентичности. Если банк меняет postedAt при обновлении одной покупки, такая доставка намеренно требует проверки.

## Excel

- В предпросмотре добавлен «Источник Excel»: существующая книга либо новый источник. Для переименованной книги пользователь выбирает прежний источник. Единственная доказанная прежняя связь по имени файла может быть предложена автоматически; несколько подходящих источников требуют выбора.
- ID строки строится из финансовых фактов и номера одинакового вхождения внутри книги, а не из имени файла/номера ячейки. Сохраняются координаты происхождения и legacy ID для совместимости.
- Перестановка строк и переименование не создают дубль при выборе того же источника. Независимые книги с одинаковыми суммами разделены account scope. Реально одинаковые строки сохраняют свою кратность.
- Старые строки сопоставляются по сохранённым source observations: дата, точные minor units, валюта, направление, продавец/описание, признаки агрегата и размещения капитала. Категория не является банковским ID.
- Изменение финансовых данных в ранее занятой ячейке, неоднозначные legacy twins, изменение числа одинаковых строк или конфликт валюты показывают причину и блокируют автоматический импорт этих строк. Ячейка используется только как сигнал возможного изменения, не как основание для перезаписи.
- Прежний счёт источника при повторном импорте не заменяется новым счётом/нулевым балансом. Канонический ID scoped по выбранному источнику, provider ID хранится отдельно.
- Точные суммы передаются в Synoball без округления. Старое предупреждение о неизбежном округлении удалено.

Ограничения: отдельный редактор разрешения неоднозначных Excel aliases не реализован; заблокированные строки видимы и не импортируются. Изменение содержимого одновременно с переименованием/перестройкой книги не всегда отличимо от новых фактов. Политика «месячный агрегат против позднее полученных детализаций» (D03), вычисление инвестиционных остатков из агрегатов и полное account ownership mapping (D01) здесь не менялись. Не следует обходить проверку созданием нового источника для той же истории.

## Банковские OCR-скриншоты

- Один и тот же imageHash в пакете читается один раз. Пустой hash отклоняется с объяснением, а не используется как общий ID для всех файлов.
- Разные изображения получают разные ID наблюдений; валюта включена даже если старый generic fingerprint её не содержал.
- Похожие строки разных изображений больше не удаляются из предпросмотра. Возможное пересечение оставляется видимым, но не выбрано автоматически. Пользователь может выбрать вторую строку, если это действительно другая покупка. Разные известные остатки/подсказки счёта не считаются доказанным пересечением.
- Новый source tag хранит hash изображения конкретной строки; исходные изображения/OCR-текст по-прежнему не записываются в Synoball.
- Legacy replay связывается со старой операцией только при доказанном изображении и совпадении фактов. Старый batch со списком нескольких изображений не доказывает происхождение отдельной строки.
- Неоднозначное пересечение с историей снимает автоматический выбор в предпросмотре. Точный replay, в том числе удалённой операции, сохраняет canonical ID и tombstone.

Ограничения: это консервативный review, не полноценное геометрическое/последовательностное выравнивание скриншотов и не автоматическое объединение любой похожей покупки. Один и тот же снимок, распознанный иначе, может требовать проверки. Экран явного выбора «дополнить конкретную старую операцию» остаётся следующей работой.
